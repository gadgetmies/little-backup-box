# OpenSpec backlog

Ideas and follow-ups that aren't ready to be (or aren't worth) full openspec changes yet. This is a plain Markdown convention, not an openspec primitive — `openspec list` does not see this file. Promote an item by running `openspec new change <kebab-name>` and remove the bullet here in the same PR.

Format per entry: one bullet stating what to do, and *why now* (or "why eventually" if it's vague). Add a pointer to the relevant code/spec/change if it makes the entry actionable.

## Soon

- **Move "reset wifi credentials" inside the WiFi tab on `/network`.** Today `Network.jsx:614-` renders the comitup AP-mode reset accordion (the "reset wifi credentials" / "Reset WiFi to AP mode" recovery action, backed by `POST /network/comitup/reset`) below the tab strip, so it shows on every tab — Network info and VPN included. It belongs under the WiFi tab specifically, since that's the tab whose configuration it resets. Update `webapp/docs/page-map.md` to match.
- **Add a catch-all 404 route in `webapp/src/App.jsx`.** Removing the legacy `/setup` / `/tools` / `/sysinfo` redirects (commit 6b853f1) means stale bookmarks now fall through React Router and render a blank page. A one-line `<Route path="*" element={<Navigate to="/" replace />} />` would route them to Backup. Defer until we see whether anyone actually hits the blank page in practice.
- **Manual smoke of the redesigned UI.** Task 10.2 of `redesign-webapp-ui-structure`: `npm run dev:mock`, click each sidebar item, every Connections tab, every Maintenance accordion. Confirm visual layout matches the page-map and the new AppBar status icon behaves as expected. (Playwright suite already verified green at 154/154 — this is the human-eyes pass.)

## Eventually

- **Replace inline `<Typography variant="h2|h3">` with `<SectionHeader>` on Storage and Network.** The pattern-system spec (`openspec/specs/webapp-ui-pattern-system/spec.md`) requires it; the conformance test does not enforce it (only h4–h6 are blocked). About a dozen call sites between the two pages. Pure refactor, no user-visible change.
- **Clean up pre-existing ESLint errors in untouched components.** `CloudConfig.jsx`, `FilterBar.jsx`, `LogMonitor.jsx`, etc. have 6 `Cannot access variable before it is declared` and `no-async-promise-executor` errors that predate any of the recent restructure work. They didn't block landing because the lint script doesn't fail CI on errors today, but they will surface the moment we tighten that.
- **Update `webapp/.PLANS/00-index.md`** to point at the new `webapp/docs/page-map.md` and `feature-catalog.md` for placement decisions. The redesign tasks claimed this would land but it didn't.
- **Add an icon to `<PageSection>` for use on Devices / Network / Storage.** Already noted as an open question in `redesign-webapp-ui-structure` design.md; deferred until first page actually wants one.
- **Restructure `/scrape` (Legacy UI).** Currently a thin index over auto-generated PHP snapshots. Out of scope for the IA redesign. Worth revisiting once the PHP UI is genuinely retired.
- **Refactor LogMonitor into a global, expandable bottom panel.** Today `LogMonitor` is a per-page component embedded inside Backup, System, and conditionally LibRawUpdater (3 instances, each with its own state). A single global panel — collapsed by default at the bottom of the layout, expandable by drag or click — would (a) give logs a consistent location across pages and (b) avoid re-mounting the SSE stream every navigation. Probably belongs in `Layout.jsx` rather than per-page.
- **Add log-message filtering by functional area.** Once the global LogMonitor lands, let users filter to just backup messages, storage operations, network, etc. Default the filter to whatever area matches the current page (e.g., on `/storage`, default-show storage messages); user can override in the panel and the override sticks for the session. Requires the device-side scripts to tag log lines with a category — coordinate with `scripts/lib_log.py` (and its callers) before doing the React side.
- **Audit existing pages against `webapp/docs/ui-pattern-system.md` and bring stragglers into compliance.** The pattern system already documents the rubric (Card vs Accordion vs Tabs) and the heading scale. The redesign change applied it to the new pages but left the bigger pre-existing pages (Storage and Network in particular) using their original Tabs structure as a deviation. This is a deeper pass: convert remaining inline `Card`/`Accordion`/`Typography variant="h2|h3"` usage to the `<PageSection>` and `<SectionHeader>` primitives across the whole webapp, and remove anywhere the rubric is violated. Subsumes the Storage/Network bullet above.
- **Review every UI string in context and rewrite for clarity.** Target: each label/helper-text earns its keep — either the control's purpose is obvious from the label alone, or the helper text adds something the user couldn't derive. Remove redundant headers (e.g., a card titled "Display" that contains a field labelled "Display theme"), redundant warnings ("Are you sure?" dialogs that repeat the action label), and decorative descriptions. Add description text only where the UI cannot communicate the purpose alone (typically: settings whose effect isn't visible until much later, or destructive ops). Will touch `webapp/public/lang/{en,de,es,fi,fr}.json` heavily; do English first, then sync others via `npm run check:i18n`.
- **Add an "advanced mode" toggle that hides expert controls in regular mode.** Default to regular. In regular mode hide: GPIO pin / fan PWM threshold (`/hardware`), debug log controls (`/system`), preset partition selectors (Backup options, Database/File operations), checksum vs file-size comparison method (Backup), the per-source/target backup-mode matrix (Preferences). Persist the toggle in `localStorage` (`lbb-advanced-mode`) and surface it in the AppBar overflow menu next to language/theme. Each hidden control needs an `if (advancedMode)` gate; no controls actually move pages.
- **Decide whether to move "Backup defaults" from `/preferences` back to `/backup`.** The redesign moved them out of the per-run Backup page on the grounds that they are *defaults*, not per-run options, and so belong with personal preferences. Counter-argument: a user configuring a new device walks through Backup once and would benefit from setting the defaults right there before running anything. Decide based on how new vs returning users actually behave; pick one location and don't split. Update `webapp/docs/{feature-catalog,page-map}.md` to match.
- **Run a fresh PHP-vs-webapp comparison and publish a navigable mapping in GitHub Pages.** The previous comparison (`webapp/.IMPLEMENTATION_DIFFERENCES.md`, the `/scrape` snapshot viewer) is stale post-redesign. Goal: a single doc that, for each PHP page, lists which webapp page/section now hosts equivalent functionality, with anchor links that resolve in the GitHub Pages build. Subsume `webapp/.IMPLEMENTATION_DIFFERENCES.md` and `webapp/.MISSING_FUNCTIONALITY.md` into the new doc; link from `webapp/docs/README.md`.
- **Sweep for unnecessary container nesting (boxes-inside-boxes).** With `<PageSection>` wrapping content that already sat inside `<Box>` and `<Stack>`, several pages now have three layers of padding/margin where one would do. Particularly noticeable in `Backup.jsx` (Options accordion contains `<Stack>` of `<Box>` of `<Stack>` of `<Box>`...) and `Maintenance.jsx` (PageSection.accordion → DatabaseOperations Stack → form Box → BackupTargetSelector Stack). Audit and remove redundant wrappers; rule of thumb is one structural wrapper per logical group.
