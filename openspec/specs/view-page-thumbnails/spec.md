## Requirements
### Requirement: Thumbnail variant on the image endpoint

`GET /api/view/image` SHALL accept an optional `variant` query parameter. When `variant=thumb`, the endpoint MUST attempt to serve the existing TIMS thumbnail file generated by `scripts/backup.py` `generateThumbnails`, located at `<storagePath>/<image.Directory>/tims/<image.File_Name>.JPG` (the `.JPG` suffix is appended verbatim to the existing filename, matching the convention in `scripts/backup.py:1449`). When `variant` is omitted or any other value, the endpoint MUST behave exactly as it does today (serve the original file unchanged).

#### Scenario: TIMS file exists

- **WHEN** a client calls `GET /api/view/image?medium=source_usb&id=42&variant=thumb` for an image whose TIMS file is present
- **THEN** the response MUST be that TIMS file with `Content-Type: image/jpeg`
- **AND** the response body MUST be byte-identical to the file on disk (no re-encoding)

#### Scenario: Default variant unchanged

- **WHEN** a client calls `GET /api/view/image?medium=source_usb&id=42` (no `variant`)
- **THEN** the endpoint MUST return the original file with the same MIME type as the file extension implies (jpeg, png, tiff, raw, …) — identical to the pre-change behaviour

### Requirement: Fallback when TIMS missing

When the TIMS thumbnail file does not exist on disk for a given image, the `variant=thumb` request MUST fall back to streaming the original file (the same code path as the no-variant case). The fallback MUST emit an `X-Thumbnail-Status: missing` response header so the frontend can detect missing thumbnails without a separate probe, and MUST log a debug-level entry naming the medium and image ID.

#### Scenario: TIMS file missing

- **WHEN** a client calls `GET /api/view/image?medium=source_usb&id=42&variant=thumb` and the TIMS file does not exist
- **THEN** the response MUST be the original file with the original MIME type and status `200`
- **AND** the response MUST include `X-Thumbnail-Status: missing`

#### Scenario: TIMS file present sets header to ok

- **WHEN** a client calls the same URL and the TIMS file does exist
- **THEN** the response MUST include `X-Thumbnail-Status: ok`

### Requirement: Grid uses thumbnail variant

The View page grid view SHALL set the `<CardMedia>` `image` URL to `/api/view/image?medium=<medium>&id=<id>&variant=thumb` for every image. The single-image view MUST continue to fetch the full-resolution variant (no `variant` parameter or an explicit non-`thumb` value) so zoom-and-pan works against the original asset.

#### Scenario: Grid card src

- **WHEN** the View grid renders an image card for image ID 7 from medium `source_usb`
- **THEN** the rendered DOM MUST contain `<img src="/api/view/image?medium=source_usb&id=7&variant=thumb" …>` and MUST NOT reference any `placehold.co` URL

#### Scenario: Single view still uses full resolution

- **WHEN** the user opens the single-image view for the same image
- **THEN** the full-resolution `<img>` MUST point at `/api/view/image?medium=source_usb&id=7` (no `variant=thumb`)

### Requirement: Cache headers

Thumbnail responses SHALL set `Cache-Control: private, max-age=86400` and an `ETag` derived from the served file's mtime and size (whether the served file is the TIMS thumbnail or the original-file fallback). The endpoint MUST honour conditional `If-None-Match` requests and return `304 Not Modified` when the ETag matches.

#### Scenario: ETag short-circuits resend

- **WHEN** a client sends `GET /api/view/image?medium=…&id=…&variant=thumb` with an `If-None-Match` header that matches the current ETag
- **THEN** the response MUST be `304 Not Modified` with no body and the same `ETag` header
- **AND** the server MUST NOT read the file body on disk again for that request

### Requirement: Mock parity for thumbnails

The mock backend (`webapp/server/utils/mockSystem.js`) and browser mock (`webapp/src/utils/mockApi.js`) SHALL serve a small static JPEG (or 1×1 transparent PNG) for any `variant=thumb` request, and a similar small static asset (or in-memory generated bytes) for the no-variant case, so e2e tests and the static GitHub Pages build never depend on real media or the TIMS pipeline.

#### Scenario: Mock thumbnail response

- **WHEN** an e2e test running with `USE_MOCKS=true` requests `GET /api/view/image?medium=source_usb&id=1&variant=thumb`
- **THEN** the response MUST be a valid image (status 200, `Content-Type` of `image/jpeg` or `image/png`) of negligible size
- **AND** the response MUST include either `X-Thumbnail-Status: ok` or `X-Thumbnail-Status: missing` so frontend assertions on that header pass under mocks
- **AND** the test MUST NOT see a network error or a placeholder URL in the rendered grid
